
## 合成验证及失败保留

24 个原生检查覆盖：自有文件读取、小型 Unicode JSON 的文件往返与管道往返、480,013 字节 JSON 的文件往返，以及超大输入、目录输入、FD 方向错误、空管道、覆盖现有输出、输入/输出/父目录符号链接、空/无效/截断密文、标准输出 FD、普通文件 FD 的拒绝。独立的沙箱哨兵还检查范围外文件读取、范围外写入和 loopback 网络均被拒绝。新版复现工具严格检查预期退出码，崩溃不能算作拒绝成功。

最初的 `deny default` 沙箱在执行简单 `/bin/cat` 时也触发启动中止，无法作为成功证据。最终采用明确的文件数据读取、写入和网络限制：允许本次作业、自制夹具、官方应用和系统依赖；只写作业目录；拒绝其他用户数据和网络。C++ 输出路径验证需要逐级打开父目录，因此仅允许精确祖先目录的读取，不递归授权其文件。系统 IPC 未限制，故这里是文件/网络约束的合成测试，并非完整的不可信进程隔离。失败尝试保留在本地审计目录，公开证据只含去路径摘要。

不把加密后字节固定成输入规范：密文可能随机化，应比较解密明文摘要与原输入摘要。codec 合成测试阶段没有读取用户草稿、账户日志、缓存媒体或权限信息；随后只读回读仅针对本次新建的自制测试工程。

## 完整工程和首次官方保存

已实际运行现有 `python3 tools/smoke_test.py`：用自制测试图案和 440 Hz 音调生成 2 秒、640×360、30 fps 的 185 格式独立草稿，包含裁切、1.5 倍速、画中画缩放/旋转/位置及中文字幕。17 个草稿文件、1 份自有媒体、两个视频轨和一个文字轨通过 build/verify-build；两类草稿元数据加解密回读和四份活动 timeline 镜像一致，源文件摘要未变。该步骤未登记草稿、未打开 UI，不证明剪映可编辑持久化；源媒体和构建摘要已写入 JSON 证据。

官方 UI 验收的最短路径是：独立生成工程 → 关闭剪映后通过现有 `publish` 事务只新增这个工程 → 从剪映主页打开 → 播放核对 → 保存 → 退出并冷重开 → 官方导出对话框输出 → 现有 `ui-export` 验证尺寸、帧率、帧数、音频和完整解码。登记流程会保留首页索引快照、检查未关联条目不变；它需要协调编辑器关闭。没有证据表明官方提供任意 `draft_info.json` 的直接导入菜单，因此不宣称无需登记即可导入。

`publish` 要求整个 `VideoFusion-macOS` 主进程退出，关闭工程或回到首页不够。它使用草稿根目录 FD 的非阻塞独占锁，先准备并校验索引副本和扩展属性，再独占放置新工程、原子替换索引，最后检查其余条目未变。已有同名工程会拒绝。本次主代理已协调退出、成功登记并从官方主页打开唯一测试工程；codec 验证工具自身不会登记草稿。

首次 UI 可见两个主轨片段、后段 1.5X、旋转画中画和完整中文字幕；播放进度由 `00:00:00:00` 到 `00:00:00:19`，最后到 `00:00:02:00`。保存并正常退出后，针对该新工程只读解密和结构检查确认：timeline schema 从 185.0.0 升至 189.0.0，保存版本为 11.6.0；工程、时间线、轨道和片段身份不变；时长、帧率和画布仍为 2 秒、30 fps、640×360；媒体绑定、裁切、速度、音量、画中画变换和字幕内容样式通过 builder 支持子集校验。四份活动镜像摘要一致且各自具有独立 inode，草稿内媒体与自制原文件摘要一致。

此次回读没有读取首页索引或其他草稿，也没有写任何 live 文件；不宣称原厂所有不透明字段逐项相同。详见 [首次保存证据](evidence/synthetic-ui-first-save-2026-10-23.json)。两张原始 UI 截图保留本地并记录摘要；因截图包含本机路径，不放进公开源码。首次打开/保存结果不能代替冷重开和导出验收。

后续冷重开已从正常 UI 完成并独立查看截图。官方导出文件通过既有 `ui-export verify`，状态 `encoded-and-decoded`，导出前后 live 草稿匹配 build，素材未变。实际文件为 `.mov`、QuickTime `qt  ` brand：格式下拉自动化未切成原计划 MP4，没有通过改名掩盖。验证器接受该 brand，因此验收成功只证明此次 MOV 成片符合尺寸、帧率、60 精确帧、H.264/AAC 和完整解码要求。视频/容器 2.0 秒，44.1 kHz 双声道 AAC 流声明为 1.996916 秒。

独立抽查导出帧 15、45、59，完整中文字幕和旋转画中画可见；再次完整解码通过。稳定窗口中正常段音调 439.9999 Hz，1.5x 段 439.9840 Hz，两声道 RMS 能量合成相对原单声道为 0.29944 / 0.29904，与 volume 0.3 一致。只证明这一 440 Hz 合成音的近似保调表现，不推断所有语音、音乐或变速策略。证据见 [官方 UI 导出独立复核](evidence/synthetic-ui-export-2026-10-23.json)。

同一个 189 保存副本随后也进入 `haoyong-video` 的现有互操作模块：strict 准确拒绝 87 条 loss，显式允许损失后真实导出另一个 2 秒、60 帧 MP4。旋转丢失、48px 自有文字样式以及 1.5x 段半帧取样差异保持可见；没有宣称无损或视觉一致。详细跨仓库证据在 [自有引擎接续报告](https://github.com/Milllkey/haoyong-video/blob/main/docs/research/JIANYING-NATIVE-INTERCHANGE-VALIDATION.md)。
