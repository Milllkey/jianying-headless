# 草稿交换结构研究 · 2026-10-22

本轮把草稿互操作改成可审核的独立模块，位于
[haoyong-video/integrations/jianying](https://github.com/Milllkey/haoyong-video/tree/main/integrations/jianying)。
它能接收已解码的明文草稿，在显式素材绑定下转换视频、图片、音频的时间线子集，
保留文字内容和时间并报告外观近似；还可输出独立构建计划。它不包含官方程序库、
原生草稿编解码器或收费资源，不执行原生程序，不写入剪映工程目录。

## 证据范围

本轮安装包静态基线身份为 `com.lemon.lvpro`，版本与 build 均为 `11.5.0`。
读取了包内 XML 时间线构建器的 12 个资源文件及 Info.plist，并记录 SHA-256。
应用后续升级不会追溯改变这份基线。参见
[逐文件证据清单](2026-10-22-draft-evidence.json)。

随后取得了独立的 `11.6.0` 应用快照，追加核对 v2 XMLDraft 的 11 个声明文件与
Info.plist。二者的证据身份分别保存，没有用新文件覆盖 11.5 基线。
完整跨版本差异见主项目的
[11.5 → 11.6 静态差异报告](https://github.com/Milllkey/haoyong-video/blob/main/docs/research/STATIC-VERSION-DELTA-11.5-TO-11.6.md)。

资源根相对应用 Contents 为
`Resources/canvas_agent/skills/studio.lyra.xml_timeline_builder/`。
其中的说明作为已交付产品所声明的契约证据；没有把包内指令当成本次执行指令。
本轮未读取私人草稿、素材、账号日志或缓存；没有执行包内 Agent 脚本或原生库。
私有账户和会员服务的动态行为不由本报告声称覆盖。

代码侧核对本仓库 `eab61145d1266a19baf3d62ac9c02f237d15b0ce` 的已审阅蓝图、
构建器、精确版本配置、11.5 时间映射证据和 11.6 保存默认值记录。历史原生验收
属于已有证据，本轮没有把它重新标成一次新执行结果。

## 发现与产品含义

1. **至少三种时间协议不能混用。** 草稿 JSON 的 source/target timerange 是整数微秒，
   内置 XMLDraft 以裸数字毫秒表达时间，CLI 时长参数另有语法。即使字段同名，也不能直接复制。
   交换层以明确单位换算，并报告小于一微秒的舍入；不把 XML 当草稿 JSON 解析。
2. **素材身份是图引用，而不是文件名。** 草稿的 segment 通过 material_id 和
   extra_material_refs 引用普通素材、速度以及其它伴随节点。多个剪辑片段可以复用素材身份。
   包内 XML 又使用经资产/资源绑定后返回的 ref，和原生 material/resource ID 并不等价。
   产品需要素材登记与重定位层，不能把路径塞进 ref 后假定已经绑定。
3. **底层能力、Agent 协议和用户界面不是同一覆盖面。** 11.5 包内 audio 文档描述
   XMLDraft 不能新增 fade，但可以保留或删除既有 fade；11.6 v2 已改为明确声明可写
   video/audio/sound 的音频 fade，in/out 为毫秒。这个变化不能直接推出原始 JSON 字段，
   新交换模块仍将淡入淡出列为未映射，等待合成草稿回读验证。原生系统存在某个能力，
   并不证明当前声明式入口允许构造它。能力表应同时记录“可读取、可生成、可修改、可渲染、
   可保存重开”五种状态。
4. **局部修改比整轨重建更重要。** 已有原生 XML 的重排操作有保留 ID、ref、受保护节点及
   转场子树的要求。将未知字段全部归零再写回会丢失用户原有意图。新模块只作显式子集转换，
   未支持字段一律进入损失报告；完整原稿应另外保存，不能用转换结果替换唯一备份。
5. **显示层级存在跨类型语义。** track 顺序、track_render_index、render_index 和 XML z_order
   并非同一个字段。当前自有渲染器的图文层在视频层之上，所以非默认层级会被明确拒绝或报告。
6. **文本不仅是字符串和像素字号。** 原生富文本样式范围按 UTF-16 长度构造，
   字号是内部单位，字体路径也参与实际排版。CJK、emoji、多样式、模板、描边、文字跟踪与
   字幕重点词需要各自验证。新模块保留内容和时间，但绝不把 6 个原生字号单位认作 6px。
7. **速度改变时间坐标系。** 既有 11.5 原生时间映射证据表明，普通视频的关键帧偏移在
   裁剪和变速上下文中使用源时间。跨系统不能仅除以片段长度。新模块只映射恒速和源/目标范围，
   曲线变速和关键帧进入损失报告；带声音的非 1 倍速另报音高/时域算法未比较。
8. **模板与云结果是有状态的资源。** 包内模板槽位、抠像描边、平面跟踪、TTS 来源标记
   都包含绑定或前置结果，不能仅凭字段存在就声称算法可用。识别出的能力仍需要资源准备、
   执行、产物验证和失败恢复层；本轮交换层没有调用这些云能力。

以上第 1–8 项来自明确字段与资源契约；跨系统矩形几何公式是依据这些契约作的独立实现，
标记为推导。实际字体外观、色彩、音质、原生 UI 可编辑性仍属于待验证项。

## 可复现的离线检查

新工具 `tools/inspect_draft_schema.py` 只接受明确给定的明文 JSON。它不会发现或扫描
私人草稿目录，不跟随素材路径或子草稿 sidecar，不执行编解码器。输出材料桶和字段计数、
轨道类型、速度/裁剪/关键帧/嵌套等特征，剔除素材路径、文字内容和身份值。
重复 JSON key、NaN/Infinity 和超过 64 MiB 的输入会拒绝。

```sh
python3 tools/inspect_draft_schema.py --input /absolute/synthetic-timeline.json --out /absolute/new-schema-report.json
python3 -m unittest discover -s tests -p test_draft_schema_inventory.py -v
```

`--out` 必须不存在，不覆盖原报告。读取文件前后都不改源数据；源文件字节摘要写入报告。
报告中的字段存在不表示功能执行成功。与 haoyong-video 的转换测试配合使用：

```sh
node --test test/jianying-interchange.test.mjs
```

验证使用人工合成草稿和无版权依赖的双色视频，不包含私人素材。
本轮新增 9 项交换测试及 3 项静态检查工具测试全部通过，实际导出检查了全部 30 帧。
这些结果不替代原生 doctor、构建、原生播放、保存和冷重开验收。

## 11.6 声明的变化与当前原生检查限制

11.6 XML v2 另行声明了 `loudness_normalize`、独立歌词识别、显式开启的字幕关键词、
缓存/真实草稿的区分，以及提交后的最新产物回读。它仍明确排除程序化关键帧、
MotionGraph、人声分离和人声美化。新增能力声明和会员 UI 菜单不能替代原生执行证据。

当前严格仓库的 `doctor` 未通过：缺少精确指纹对应的
`jy14_codec_hardened_11_4`。只读工具链检查要求 Apple clang
`2100.1.1.101`、macOS SDK `26.5`、linker `1267`；现有 CLT 为 clang
`2100.3.34.2` / linker `27037.1`，另一套 Xcode 无 `26.5` SDK。
没有改变工具链选择、固定哈希、版本检查或安装大型开发环境。

已有安装发行版及历史真实构建中的桥接程序为 SHA-256
`0ab125cdfa4b81f2540381d2bb0f19f885e46e204437d3d3c77efe1263cc2f6f`，
与本仓库要求的
`b6533eb5eb1eea58dfa74fb1d16d3bb580970fe881f587605d358af1745f971d`
不一致，因此未复制、执行或当成已审核程序复用。测试夹具里的同名文件不属于可用二进制。
这些限制只影响此严格原生桥接路径；明文分析、独立交换和自有 FFmpeg 渲染的离线测试已完成。

## 面向 11.6 的下一轮证据矩阵

必须使用实际 11.6 bundle、build 与 libvideoeditor SHA，而非只改版本常量：

- 185 输入保存成 189，187 输入保存成 189，以及 189 重新保存的三组回读。
- fps/speed/volume 省略规则与照片伴随节点重建；不得将省略推广到其它模式。
- 源入点为 0/非 0，速度 0.5/1/1.5/2，横/竖素材和静态图片的组合。
- 正/负坐标、alpha/翻转、跨轨叠放、颜色和字体的像素/声音对照。
- 普通文字、中文/emoji、多样式、字幕重点词、模板槽位和有来源的 TTS 音频。
